# v1.8.4 Cross-Device and State-Integrity Acceptance

This phase does not create a new canonical state owner. It hardens the existing cloud/lifecycle protections and requires the existing integration suite to remain authoritative.

Required protected scenarios:
- same record edited on two devices
- stale local revision versus newer cloud revision
- offline edit and reconnect
- interrupted sync and retry
- retained offspring continuity
- sale/transfer provenance and duplicate protection
- stale-device deletion/tombstone protection
- cross-device breeding/litter continuity
- canonical Weight ownership in Health
- task recurrence/idempotency
- backup/export and recovery
- last-known-good recovery and conflict diagnostics
- no silent record deletion

A failing scenario must be repaired in the owning lifecycle/state/sync layer. Lifecycle rules must not be weakened to satisfy tests.
