# HerdHarbor 2.0.1 — S10 session refresh and save integrity

This is an unmerged stabilization layer on S9 #493. Stable production 2.0.0 remains unchanged.

## Changes
- Cloud `auth-boundary` now fires immediately on true sign-in/sign-out/password recovery, or when a token refresh / user update changes the authenticated user ID. Same-account token refresh no longer pretends to be an account switch.
- Paper pedigree and record photo listeners distinguish a hydrated `auth-session` update from the immediate `auth-boundary` event. They preserve a review for the same signed-in user, while true account changes still cancel ongoing preparation/review, including rapid A→B→A transitions.
- A failed existing/new animal save now restores animal data, saved breed-suggestion map and activity history; no session-only breed appears from an uncommitted change.
- Failed AI pedigree attachment cleanup is no longer swallowed. Deletion is retried once; if still unsuccessful, the user sees a warning that a temporary local image may remain. The error is logged without the image itself. No unsuccessful import is reported as successful.

## Regression tests
- Complete in-flight paper review retained after same-account session update.
- True auth boundary still cancels it.
- Failed animal edit/new-animal save restores state; successful saves retain new breeds.
- Repeated IndexedDB cleanup failure raises explicit warning and leaves canonical state unchanged.

## Next required release work
The installed PWA 2.0.1 build/cache identity and offline canine asset preload must be cut over **together**, separately from S10 to keep regression isolation. End-to-end two-account sync and genuine iOS/desktop PDF print captures remain necessary; these are not proven by automated CI.
