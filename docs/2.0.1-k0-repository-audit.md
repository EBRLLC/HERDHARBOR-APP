## Known risks and targeted regressions
- The generic animal form defaults a new species to Rabbit and stores a single legacy registration number. A dog editor must add *optional*, repeatable canine registration and title records, never rewrite the rabbit registration field.
- `pedigree-renderer-v2.0.0.js` field `prefix` is rabbitry/breeder identity, not a dog's championship title prefix.
- `paper-pedigree-import-core-v1.8.2.js` defaults unspecified species to Rabbit; paper pedigree AI needs distinct dog support and hard canonical conflict validation.
- `animal-action-router-v1.8.3.js` offers a generic breeding action; a Dog must not launch a rabbit mating/breeding form.
- Birth certificate shared print/footer behavior was fixed on main October 13; preserve its one-page regression contract.
- CI `v2.0.0-ci.yml` initially checked only `main` plus old branch patterns. Add explicit 2.0.1 stacked branch-target patterns to run checks rather than falsely reporting "no checks" as green.
- `main` still has the verified stable 2.0.0 production marker; do not bump that marker in K0 or deploy.

## Baseline inventory
- `248` Node `tests/*.test.cjs` files on audited main; CI executes each independently in UTC and America/New_York, plus security, governance, state integrity, monitoring and Android unsigned AAB review.
- No test runner was run locally in K0: the terminal runtime could not resolve github.com. Only GitHub-connected repository/API inspection was available. Treat CI runs on the PR as the actual execution evidence.
- No screenshots, test farms, browser UI walk-through, RLS deployment, production access, or AI entitlement approvals are claimed by K0.

## Review stop rule
Stack: K0 → K1 → K2 → K3 → K4 → A1 → A2 → A3 → K5 → R1. Each PR targets the preceding branch. Keep all PRs unmerged and no production flags switched. Work is complete **only** when the final R1 PR is non-draft, required checks have completed green, no tests are missing, and the owner can review it.
