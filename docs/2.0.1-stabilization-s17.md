## Reproduced failures and repairs

### A — unattributed recovery

Executable tests extract the actual `ensureAuthenticatedAccountBoundary` function.
Before repair, a paused A archive cleared B's replacement workspace, A→B→A reused
an obsolete same-user promise, and same-session replacement drafts were cleared.
An archival rejection escaped without a normalized failure result.

Recovery now checks the generation token and live session after archival and
compares the exact raw workspace, active owner, and legacy owner before clearing.
Only explicit archive success authorizes clearing. Owner writes require readback.
Stale recovery neither resets runtime nor changes session markers or ownership.
Malformed/non-object active JSON and inaccessible storage fail closed. The cached
promise carries its generation and returns the same guarded failure to concurrent
same-generation callers. Ordinary owner transitions also guard destructive adapters
against stale generations. Startup marker cleanup rechecks the returned token.

No storage keys, schema, RPC, RLS policy, species mapper, or hydration fallback
selection was changed. Unattributed archives remain unattributed; they are not
installed into the incoming account's cache.

### B — legacy 2.0.0 navigation: RELEASE BLOCKER S17-B-LEGACY-TIMER

`tests/fixtures/pwa-main-72e6ea7.txt` is the exact base-main `pwa.js` (not a rewritten
mock). The regression executes its real activation and reload functions against
the candidate worker. A dirty second tab blocks worker activation, yet the old
8-second timeout still calls cache-busting `location.replace`.

The S16 exception treating `SKIP_WAITING` as readiness is removed. Every editing
client must answer the readiness protocol, including the sender. A silent legacy
client cannot authorize activation even after Update Now. Current 2.0.1 clients
retain the existing unsynced/modal/paper/photo guards and controllerchange-only
reload. Updated guidance says to save and close older tabs/app windows.

A waiting worker CAN defer `skipWaiting`, query responsive clients, and preserve
existing caches. It CANNOT inspect old pages' DOM/in-memory drafts, cancel their
JavaScript timers, install new message listeners into already-loaded documents,
or prevent page-controlled `location.replace`. Sending a deferred message does
not fix a page that has no listener. Green tests do not mean this legacy behavior
has been repaired retroactively.

### Required conservative migration procedure — approval and device proof pending

1. Before exposing the release to legacy clients, arrange an owner-approved
   transition with users. Save/commit all animal/litter/edit/review forms and
   verify offline work is durably saved; do not sign out, clear site data, or
   delete caches as an update workaround.
2. Do NOT press Update Now in a potentially dirty 2.0.0 page. If its timer has
   already been started, the candidate worker cannot guarantee draft protection.
3. After saving, close all legacy browser tabs and installed app windows in that
   browser profile. The natural worker lifecycle can then activate without
   navigating a live editor. Reopen online and verify the new version, saved
   records and offline reopening. Repeat independently on each device/profile.
4. Mixed-version sessions remain deferred until legacy clients are safely closed.
   A modern clean tab can retry after closing the old windows. Read-only How-To
   tabs use the reviewed exception below.
5. Verify iOS Safari and Android installed-PWA save/close/reopen behavior, including
   offline pending edits, before lifting the blocker. No real-device run is claimed.

### Separately reviewable bridge proposal (NOT deployed or implemented on main)

Proposed PR title: **2.0.0 safety bridge — readiness handshake and no forced reload**.
Proposed base: the then-current verified 2.0.0 main; proposed branch:
`herdharbor-2.0.0/pwa-safety-bridge`. Scope: old 2.0.0 `pwa.js`, worker, coordinated
asset fingerprints and executable tests only. Add the current draft/unsynced guards,
readiness listener, controllerchange-confirmed reload, and remove timeout navigation;
keep the worker fail-closed. Do not include canine/AI or schema changes.

A bridge only protects pages after they LOAD the bridge. Its initial rollout still
requires saved/closed legacy pages or another independently verified owner-approved
migration control. It is not a way to rewrite code already executing in a tab.
Deploying either bridge or 2.0.1 needs separate approval. Until the migration control
is accepted and verified, **SAFE TO MERGE: NO**.

### C — static How-To clients

Only same-origin, top-level WindowClients with nonempty client IDs at the exact
scope-relative `how-to/` and `how-to/index.html` paths are exempt from editing
readiness replies. These source documents have only ephemeral search/feedback
controls and no application/storage/network engines. Query/fragment variations
are safe because the audited script does not consume them. Unknown subpaths,
account/admin/app pages and foreign origins are never exempted.

The worker snapshots client IDs and URLs and rescans after asynchronous readiness
responses. Navigation/redirect to an app URL, a changed query/fragment, a new
client or a removed client causes deferral and a later retry. Tests cover a docs
client becoming a dirty app client during the check. A source contract test rejects
future external scripts, forms/editors, storage/network engines or query-driven
behavior in the exempt document; such additions require removing/reviewing the
exception.

Navigation caching remains route-specific: How-To never replaces app home. The
active shell plus two prior release caches are retained. Deferral runs no cache
deletion. No additional shell cache or duplicate lazy-asset inventory is introduced;
absolute device cache bytes remain unmeasured and require device inspection.
