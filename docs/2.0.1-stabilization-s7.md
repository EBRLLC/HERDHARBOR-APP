# S7 — Asynchronous photo account isolation and safe animal deletion

This stabilization branch targets S6 #490. It deliberately changes no live user data, Supabase policies, schema, or production deployment.

## Photo AI safety
- Each analysis takes an immutable snapshot of the initiating signed-in user, selected image object and request generation, checked at the end of asynchronous image preparation and immediately before network transmission (including delayed offline retries).
- Consent withdrawal, selecting another image, cancelling the modal, and opening a new capture invalidate the generation and clear queued payloads. Stale responses cannot populate the review UI or be accepted.
- Request metadata is stripped before transmission; the server still independently verifies authentication, entitlement, and `aiOptIn`.
- Cloud authentication boundary events clear pending photo work when the signed-in identity changes. A return to the previous identity does not resurrect the discarded upload. Draft confirmation additionally checks the original account.
- In-flight HTTP calls that have **already been dispatched cannot be un-sent**; any returned draft is discarded after a state change. This is distinguished from preventing pre-dispatch/queued uploads.
- The existing manual animal/health workflows remain available without AI.

## Destructive record safety
- A general dependency check rejects removal of any animal still referenced by offspring, litters, births, breedings, health, pedigrees (including ancestor snapshots), drafts, tasks, sales, ownership transfers, shows or weight records. Archive/Ancestor Only is safer than implicit cascade deletion.
- For an unreferenced animal, the UI removes the record and commits it only after confirmation. If local durable persistence fails, it restores both animal and activity data and leaves the dialog open. It does not report a completed deletion.
- The existing multi-species home, task, pedigree and AI schema are not altered.

## Regression acceptance
The new `tests/v2.0.1-stabilization-async-deletion.test.cjs` reproduces (1) revocation during image preparation, (2) A→B account switch while offline, (3) auth switch and return, (4) replacing an image during active extraction, (5) cancelling an active extraction, (6) dependent animal deletion, (7) failed local durable save, and (8) safe unreferenced deletion. This file is included by the inherited `npm run test:v2.0.1-review` wildcard.
