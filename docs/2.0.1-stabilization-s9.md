# HerdHarbor 2.0.1 S9 — Early authentication boundaries and durable pedigree attachments

S9 is stacked on green S8 #492, without merging or deploying previous PRs or changing live Supabase state.

## Findings corrected
- A SIGNED_IN event previously could dispatch `herdharbor:auth-session` *after* awaiting asynchronous cloud account-boundary recovery/hydration. An A→B→A transition could briefly evade a client photo cancellation check. Cloud now emits a separate `herdharbor:auth-boundary` signal immediately when authentication events arrive, **before any asynchronous work**, and both AI photo workflows subscribe to it as well as the existing session event. This does not replace authoritative server authentication.
- The paper AI importer previously reused `pedigree_ai_<extractionId>` as an IndexedDB attachment key. A repeated extraction with the same ID could overwrite an earlier document image and failed-import cleanup could delete that earlier image. Imported records now have per-import collision-checked unique keys, preserving original extraction identity as a prefix.
- The IndexedDB attachment writer previously resolved after the request's `onsuccess`, before the transaction had committed. It now waits for `transaction.oncomplete`, and handles transaction abort/error as failed storage.
- Closing the paper dialog while its attachment/import commit was still pending previously reset the shared `commitPending` guard. That guard is now owned by the commit operation through its finally block; reopening is denied until the pending operation completes.

## Additional regression coverage
- Immediate auth boundary while preparing a photo, before any awaited account hydration
- Two successful imports from the identical AI extraction produce distinct pedigree IDs and two retained attachment keys
- A failed second import cannot erase the existing first attachment
- Transactional IndexedDB completion contract and new auth boundary dispatch ordering

## Existing boundaries
The paper reader is Rabbit-only and opt-in; manual entry is available without AI. No public AI entitlement is activated. No production data, Supabase policy, schema, branch, or user state is merged/deployed. Owner signoff still requires live two-account/cross-device sync tests and actual phone/desktop PDF rendering checks.
