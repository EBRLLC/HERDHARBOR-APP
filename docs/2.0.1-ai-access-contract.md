## Server authorization before any paid AI image call
Each Edge Function independently enforces all of the following with its existing authenticated Supabase service-role client:
1. Global `HERDHARBOR_AI_PUBLIC_ENABLED=true`; absent/false means disabled.
2. Action-specific `HERDHARBOR_AI_PAPER_PEDIGREE_ENABLED=true` or `HERDHARBOR_AI_PHOTO_ENTRY_ENABLED=true`; default disabled and independent.
3. Exact request `aiOptIn: true`, never inferred from login or a browser-local tester flag.
4. Current `account_access` row with `account_status=active`, read from the service-role connection, not arbitrary browser JWT user metadata.
5. An explicit operator-approved tier listed in `HERDHARBOR_AI_APPROVED_TIERS` and subscription status active/trialing, OR a trusted operator-populated `HERDHARBOR_AI_APPROVED_PILOT_USER_IDS` entry. Both lists default empty. A pilot does **not** override a non-active account.
6. Existing separate provider image validation, per-user/global quota reservation and timeout/rate-limits. The new access check runs **before** usage reservation.
7. No new AI state write path. A provider result remains a draft; canonical save still requires user review.

`HERDHARBOR_AI_APPROVED_PILOT_USER_IDS` is a protected Edge environment configuration only; do not place member identifiers in frontend, repo code, metrics or logs. No wildcard/all-users fallback. Never use `raw_user_meta_data` as role authority.

## Operational stop switches
Either per-tool switch disables its own provider without changing saved animal records. The top-level AI switch disables all paid image AI. All three default to OFF for unapproved general release. Existing voice transcription uses device/browser speech support; avoid claiming that an Edge image quota applies to it, and keep its own optional UI gate and human review boundary.

## Deployment and approval
This stack only changes GitHub code; **no Supabase function deployment or database migration has been executed**. Existing production behavior is untouched until approved promotion. Before a public switch, complete A2/A3 opt-in UI and draft acceptance, test server denial with real Member/Founder/Junior test accounts and mocked provider failure, verify network session isolation, then obtain explicit owner approval for each eligible tier. Missing approval is a release activation blocker, not a reason to invent eligibility. The shared manual app must work when every AI switch is off.
