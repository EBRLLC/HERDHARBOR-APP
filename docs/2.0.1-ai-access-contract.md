# HerdHarbor 2.0.1 — AI access and release controls

Status: **implementation under review**. Public enablement is **OFF**. Do not change live Supabase secrets or feature switches before owner approval and R1 acceptance.

## Findings from current production architecture
- Before this patch, AI tester visibility was based on the browser's `herdharbor_ai_live_tester_v1` localStorage key. This must not be treated as server authorization.
- Paper and photo endpoints authenticated the Supabase user and imposed quota controls, but did **not** independently enforce pilot tester membership or subscription tier access.
- Existing account authority is `public.account_access`: `user_id`, `membership_tier`, `account_status`, `subscription_status`. Its RLS remains unchanged. Service-role reads inside the Edge Functions are restricted to the authenticated user's row.
- Voice is currently browser-local speech/text parsing with canonical form handoff. It does not invoke an AI cloud Edge Function or consume image quota. Voice cannot be described as an OpenAI-backed voice model. Its browser tester visibility is separate from backend image AI grants.

## Implemented backend policy
- The paper pedigree and record photo Edge Functions revalidate authenticated user identity, read that user's authoritative `account_access`, and enforce `decideAiAccess` **before reading image payload, reserving quota, or invoking provider**.
- Fail closed on missing accounts or membership, suspended/inactive accounts, policy query errors, or absent server settings. Do not use client tier claims, browser flags, `user_metadata`, provider payloads, or URL query parameters for authorization.
- Emergency switches `HH_AI_PAPER_DISABLED=true` and `HH_AI_PHOTO_DISABLED=true` deny each operation individually, even to testers.
- `HH_AI_TESTER_USER_IDS` is a server-only comma-separated list of authenticated user IDs for *adult Member/Founder* pilot accounts; Junior remains denied even if allowlisted. Do not add IDs in Git. A missing allowlist means no pilot access.
- Public access requires all three simultaneously: per-operation `HH_AI_PAPER_PUBLIC_ENABLED=true` / `HH_AI_PHOTO_PUBLIC_ENABLED=true`, `HH_AI_ENTITLEMENT_MATRIX_APPROVED=true`, and the tier in the corresponding `HH_AI_PAPER_APPROVED_TIERS` / `HH_AI_PHOTO_APPROVED_TIERS`. Additionally the account must be active with `active`/`trialing` subscription. These settings are all server-side and default to OFF/empty.
- No changes to pricing, subscription tables, provider keys, database schema, RLS, or existing daily quota RPCs. No Supabase deployment or live environment changes in this branch.

## Per-request opt-in (S6 hardening)
The paper and record-photo image endpoints additionally require `body.aiOptIn === true` after authenticated entitlement checks and before provider quota reservation. Each UI upload presents a separate, unchecked choice; selecting a new file resets it. Queued record-photo retries are cancelled when consent is withdrawn. Client consent never overrides the account/tier policy. Do not treat browser tester visibility as consent or authorization.

## Operational rollout
1. Deploy **only after merging a fully reviewed green release**, not from this PR branch. Keep public switches off.
2. Configure trusted tester IDs securely if controlled testers require service access; verify 403 denial from a second non-allowlisted signed-in user.
3. Validate each kill switch, successful pilot review draft, quota exhaustion, provider unavailable, and manual fallback.
4. Obtain owner approval of tier matrix and consent/usage messaging before any public switch.
5. Reverse a public switch or set the operation-specific disable key for immediate disable, without deleting any animal or pedigree data.

## Remaining acceptance boundaries
- Browser visibility flag is **not an access decision**. A subsequent UX track should replace tester-oriented controls with an opt-in UI tied to a server-authoritative eligibility result.
- Canine paper-pedigree AI remains OFF until separately validated against a real canine image corpus, including title placement and uncertain lineage.
- Voice tester-only access is not enforced by an AI Edge Function because it runs locally. Any future cloud-based voice provider must receive its own server-enforced entitlement, quota and disable gate before public exposure.
