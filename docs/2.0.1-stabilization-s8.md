# HerdHarbor 2.0.1 — S8 paper AI lifecycle and failure-atomic commits

S8 targets the final S7 PR #491. No production migration, deployment, merge, public AI activation, or member-data mutation is included.

## Paper pedigree AI

- A paper AI attempt captures an immutable initiating account ID, selected file and generation before reading the image.
- The request is cancelled when consent is withdrawn, the file changes, the dialog closes or any cloud authentication-boundary event occurs, including Account A → B → A.
- The same conditions are checked **after** asynchronous image preparation and **immediately before** provider invocation, then again after the provider returns. A returned response from a cancelled attempt cannot become a review draft.
- The local preview also checks file generation, avoiding a stale preview after selecting a replacement photo.
- Importing a reviewed draft requires the original account, file, consent, generation and active dialog to remain valid, including **after the awaited IndexedDB attachment write**. It also rejects a farm state that was replaced while the attachment was being stored.
- When an attachment has been started but the corresponding pedigree cannot be committed, the importer attempts to remove the pending attachment. An already-dispatched AI service call cannot be recalled, but its response is ignored when no longer current.

## Record photo

Any `herdharbor:auth-session` event invalidates the in-progress record-photo job, including jobs awaiting image preparation where no queued payload exists. A → B → A cannot reuse the first attempt or its original consent.

## Canonical state

`HerdHarborApp.commitState` holds a reference to the last active state until a successful synchronous canonical-store commit. A failed or throwing durable commit restores the previous state reference. In the paper import workflow the candidate is constructed from a clone, so failure does not mutate the previous farm data. Existing `saveState` error feedback remains intact.

## Acceptance

Added executable regression cases for revoked consent during preparation, A → B → A auth changes, replacement photo after provider dispatch, closing an active review, false/throwing `commitState`, and failure-driven attachment cleanup. These run in the inherited `npm run test:v2.0.1-review` gate.
