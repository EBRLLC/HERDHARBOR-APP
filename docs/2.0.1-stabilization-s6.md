# HerdHarbor 2.0.1 — S6 explicit AI upload consent

The chosen release chain is K0 → K1 → K2 → K3 → K4 → A1 (#479) → A2 (#481) → A3 → K5 → R1 → S1 → S2 → S3 → S4 → S5 → S6.

Two older alternative AI branches (#478/#480) contain useful affirmative opt-in semantics but have incompatible AI access modules and entitlement environment variable names. S6 ports the **consent requirement only** into the selected and audited server-authoritative entitlement implementation. Those alternates are not merged.

## Consent semantics
- On paper-pedigree AI, the user must check an initially unchecked consent box authorizing the specific rabbit pedigree image before pressing Read. Changing the file clears the checkbox. Manual entry remains a separate, no-AI path.
- On record-photo AI, the user must opt in before image preparation and upload. Changing the file clears consent. Unchecking consent clears any queued offline retry; queued consent is revalidated on resume. Cancel also clears pending retries.
- Both authenticated Supabase image Edge Functions enforce `body.aiOptIn === true` after the account access gate but **before validating an image, reserving quota or calling the provider**. This is request-specific confirmation, not a substitute for server-side authorization. No consent is persisted as an entitlement.
- No Junior/public access is enabled by this PR. All service switches and the approved tier matrix remain governed by `supabase/functions/_shared/herdharbor-ai-access-v2.0.1.ts` and default to disabled.
- The user can perform all manual Animal, Health and Pedigree workflows without these checks, quota or provider availability.

## Strict release acceptance
- Check that a signed-in allowed tester without consent receives `consent_required` and incurs zero provider requests and zero quota reservations.
- Inspect account isolation, offline resume, cancellation and device revocation with two real test accounts.
- Do not deploy either Edge Function or enable public AI until the owner explicitly approves an AI tier/consent policy and the full stack has passed final review.

This branch changes only GitHub code and tests. It does not merge, deploy, migrate, or alter live accounts.
