# HerdHarbor 2.0.1 S2 — Canine identity and legacy UI stabilization

- Legacy `openAnimalDetail` modal is still reachable from animal cards. Dogs now show their registered name, recorded titles and registry numbers, plus a dedicated unofficial canine print button. The modal no longer shows rabbit-only build/import, birth certificate, linebreeding, or document-center actions when the animal is Dog; those controls remain for non-dog species.
- Canine registered names, call names, registration numbers, registry+number combinations and title abbreviations are searchable in the existing animal grid. Existing Rabbit fields remain indexed unchanged.
- Photo-assisted identity matching now recognizes breeder-maintained Dog registry records and registered names, preserving unique-match requirements. Ambiguous identical names still require an explicit animal selection. The AI registration flow warns when an identity already exists rather than claiming a new record is unique.
- Removing a Dog's preferred registration will clear the deleted preferred identifier when the editor is saved. Other registry records remain untouched.
- This PR does not change server-side authorization, registry certification, legacy rabbit serialization, persistence schema, or AI public access.

Risk/limits: Global Rabbits-oriented import tools remain visible under the general Animals header for the existing rabbit workflow. No new canine AI scanning capability is claimed. Additional lineage traversal and print consistency stabilization follows in S3.
