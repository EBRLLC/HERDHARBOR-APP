## Required device and multi-account acceptance (owner or approved QA operator)
- [ ] iPhone-sized browser/PWA and desktop: account with an existing Holland Lop and Golden Retriever in the *same home directory*, same back navigation.
- [ ] Rabbit profile: enter breeder actions and print a normal rabbit pedigree; compare against a pre-2.0.1 reference PDF or screenshot.
- [ ] Dog profile: edit call/registered name and repeatable registry/title records; verify prefix/suffix order and no false registry-verification claims.
- [ ] Dog ancestors: create sire/dam Dog and Ancestor Only references; reject rabbit parent, circular parent and same-name duplicate; confirm ancestors do not appear as active stock.
- [ ] Dog pedigree: capture readable *actual* Letter and A4 outputs for 3 and 4 generations on desktop and iPhone-size; stress long registered names, many titles, missing/repeated ancestors. Verify complete text in PDF appendix and no unexpected clipped pages.
- [ ] Shared Today: dog manual task and Health follow-up appear once alongside rabbit tasks; mark completed/reopen, reload, verify no duplicate; confirm historical ancestor creates no operational task.
- [ ] Cross-device: signed-in Account A and Account B cannot read or mutate each other's animals; login/logout/anonymous recovery, offline edits, CAS conflict and controlled dual-write stay sound.
- [ ] Attempt manipulated API/JSON payloads: no cross-account read/write, wrong-species parentage or unreviewed AI commit. Current browser/domain validation is **not** a server-side JSON semantic schema validation: this requires explicit adversarial acceptance.
- [ ] AI OFF: all manual animal, pedigree, Health and document functions operate without quota, provider, opt-in or AI setup.
- [ ] Eligible allowlisted pilot: paper photo creates an editable draft; cancel results in zero saves; contradictory/uncertain lineage cannot auto-commit. Rabbit-only AI scan; canine scan denied until separate corpus approved.
- [ ] Photo/voice reviewed drafts: wrong species/date/animal remain unresolved; confirm leads to existing canonical form; cancel does not persist content.
- [ ] AI server switches: independent paper/photo kill switch, denied Junior/unapproved tiers, quota exhausted, invalid session, provider outage and no sensitive provider/text/image/health data in logs.
- [ ] Admin/account controls, payment plans, fallback-only Free Adult, Marketplace and existing cattle/goat/rabbit workflows unchanged.
- [ ] Protected feature switches and migration/RLS changes checked: no schema change in this PR stack. Before enabling any public AI, owner approves the access matrix in `docs/2.0.1-ai-access-contract.md`.
- [ ] Build provenance: exact green final PR SHA, reviewer approval and merge order confirmed before any production merge/flag enable; verify `main` and deployment commit only after separate authorization.

## Known limits / no-go for public promotion
1. AI public eligibility matrix **not owner-approved**; public flags remain off, server tester allowlist is required for pilot access.
2. Canine paper AI has **no verified field-by-field image reference corpus**; remains disabled.
3. Browser-based print/mobile/accessibility/device acceptance and account-isolation adversarial testing cannot be claimed solely from GitHub CI. Do not sign these off without evidence.
4. Current canine sire/dam semantic validation happens in application/domain code. Supabase RLS prevents user ownership crossing at row level, but arbitrary tampered JSON inside one's *own* herd is not server-validated as canine lineage schema. Owner must decide whether to require an additional server-side semantic gate before public enablement; do not claim one exists.
5. New registered canine pedigrees are HerdHarbor breeder-maintained records, not AKC certification or independently verified registrations/titles.
6. Native phone push, app-store release and full canine reproduction are out of scope.

## Rollback and production authority
- No migration, deletion, sync cohort change or production flag enablement is part of these PRs.
- Keep `main` at stable 2.0.0 until owner review. Public AI access defaults OFF; independent `HH_AI_PAPER_DISABLED`/`HH_AI_PHOTO_DISABLED` keys stop image calls immediately after an approved server release, without deleting canonical records.
- Disabling canine UI must not delete saved animals. Never roll back by clearing local or cloud user data.
- After owner signoff, merge PRs **one by one** in ancestry order, retargeting and rerunning required CI after any change. Do not force merge red checks.
- Recheck deployed exact SHA and operational logs only after explicit separate release authorization.

## Stop rule for engineering handoff
Stop when **the final R1 PR is open, non-draft, green on every required check, mergeable and ready for owner review**. Do not merge or deploy. Report final PR/head SHA, predecessor links and outstanding owner-only acceptance gates accurately.
