## Non-negotiable open acceptance requirements
- **AKC issue #510:** Do not represent the 205 breed AKC colors/markings, three-digit registration codes, breed-specific health requirements, or conformation criteria as fully sourced. Existing validated selection covers an initial subset; all remaining rows are explicit gaps. A comprehensive sourced catalog review is required.
- **Real persistence:** JSON serialization is not an isolated normalized-cloud database test. Verify offline, cross-device sync, account switching, conflict/merge, sign-in after app upgrade, failed and interrupted writes, and read-back from an isolated Supabase instance before approving release.
- **Actual browser:** Source-level dependency/order tests and Node modules are not substitutes for browser and mobile UI automation. Validate modal interactions, species changes, information persistence, keyboard focus, PWA cache refresh, Android.
- **Feline/cavy registration:** Manual registry data is unverified. Registry/cattery show rules and evidence, printable pedigree output, professional transfer documents and all approved UX items require further acceptance.
- **Canine:** Full heat-cycle/mating/puppy end-to-end QA, veterinary test classifications and performance analytics still require review.
- **Schema and cloud:** Confirm that nested feline/cavy/puppy evidence survives normalized serializer, sanitization, RLS, and migration; do not add production database columns or write production rows to test.
- **Reminders:** Cavy follow-up dates and feline planning estimates are displayed locally; notification synchronization across all species remains an acceptance item.
- **Cavy welfare:** Exposure, gestation and separation dates are planning records, not diagnoses or husbandry guidance. Do not auto-certify clinical outcomes.
- **Release:** Only a staged, confirmed CI run for exact B14 head plus manual gates can support a release-ready claim.
