# 2.0.1 S5 — Legacy reconciliation and shared pedigree dispatch

Code-only stabilization review. Source parent: S4 PR #488. No production deployment, migration, public AI access, merging, or member-data mutation.

## Changes
- Reverse-parent validation now checks newly changed sex/species/link values. Incomplete sex in an existing Rabbit/Goat/Cattle parent **does not** prevent unrelated name/status edits. Canine parent transitions and genuine sex changes that would break references remain blocked.
- Task automation fingerprints now derive from reminder lifecycle (due date, linked animal, source identity, reminder type, recurrence) rather than title/category/notes. The reconciler compares semantic *pre-update task fields* to new definitions, not old persisted hash strings. Therefore completed reminders don't reopen when a dog label or animal name changes; actual source follow-up date changes still reopen according to existing rules.
- `openPrintPedigreeForm` is the shared print entry from saved pedigree and legacy animal routes. It dispatches Dog to `HerdHarborCaninePedigreePrint`, fails closed when unavailable, and leaves non-Dog print customization unchanged. No direct dog sale-pedigree fallback.
- Added execution-level tests for unknown-sex livestock editing, historical task fingerprints, genuine rescheduling and print dispatch. The final 2.0.1 review command already includes all `tests/v2.0.1-stabilization-*.test.cjs`.
