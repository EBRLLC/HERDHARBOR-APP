# 2.0.1 K5 — One Today and Tasks queue for mixed herds

This branch **extends the existing task automation/runtime**. It does not introduce a separate canine task table, notification state, scheduler, or duplicate dashboard.

- A manual task may be linked to Dog, Rabbit or another current animal through the existing animal selector and canonical `state.tasks`.
- A Dog Health follow-up with an actual `followUpDate` derives a stable task ID in exactly the same task collection as a rabbit follow-up. Dog title includes `(Dog)` to distinguish same-named animals.
- Task list display derives `Dog` from the linked current animal. No species shadow field is persisted on tasks.
- Historical Dog records (`Sold`, `Deceased`, `Archived`, `Ancestor Only`) do not generate new Health reminder definitions, but previously created automation-managed reminders remain active until the user completes or reconciles them.
- Existing rabbit reminders remain unchanged. Previously recorded canine breeding/litter follow-up tasks remain generated using their existing IDs; no new canine reproduction entry workflow is exposed.
- Task completion/reopen and recurring task deduplication remain authoritative in `task-runtime-v1.8.3.js`; stable fingerprints/IDs remain unchanged.
- Notification delivery is the existing Today/Task UI. Do not claim background native phone push notifications from this branch.

No Supabase schema/migrations, cloud rollout, production deployment, or new account/staff role changes were made.

R1 must verify mixed accounts, reload/cloud CAS, duplicate prevention and manual reminder completion in browser-based acceptance; CI only validates code and the existing regression suite.
