# 2.0.1 S4 — Paper AI species gate tightening

The existing paper reader and its model are validated for Rabbit only. The server no longer silently assumes a missing `species` request means Rabbit. A client must explicitly declare `species: "Rabbit"` (the 2.0.1 reader already does this). This is a requested context label, not evidence that the image actually depicts a rabbit.

After model extraction, **every present extracted node must explicitly carry Rabbit species**. If a model leaves the species blank, contradicts Rabbit, or cannot classify the document, the server rejects the draft. The underlying user data remains unchanged and manual records remain fully usable.

This strict behavior intentionally favors false rejections over misclassifying canine pedigrees as rabbit ancestry. Some older rabbit pedigrees without identifiable printed breed/species information may no longer pass automated image extraction; users can still enter the records manually. A Rabbit request label alone is never treated as a substitute for model-side species evidence.

The previous client importer contains Rabbit-default normalization for backward compatibility with local draft formats. This patch does not remove that local default, but newly successful server responses must satisfy the stronger explicit-species rule before the client can receive them. End-to-end image accuracy is **not** established without a real image corpus.

No Edge Function deployed and no public AI flags activated. Repeat real-image and no-provider checks with owner-authorized tester accounts prior to production.
