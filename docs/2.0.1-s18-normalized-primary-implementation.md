# HerdHarbor 2.0.1 — S18 normalized-primary transition

## Purpose

Replace the legacy full-state PATCH as the normal, authoritative save **only after a per-account verified normalized cutover**. Do not simply route dual-write accounts to normalized APIs while their server manifest still says `dual_write`. The server's stage, record authority, writer CAS baseline, and authenticated account fencing must agree.

## Implemented on the S18 candidate

- New `HerdHarborNormalizedSyncRollout.cutoverToNormalizedPrimary({ownerApproved,legacyClientsClosed,backupVerified})` is explicit and fail-closed. It requires owner-accepted migration, closed legacy editing clients, verified recovery backup, verified online/current session, no local or record-outbox mutations, no conflicts, three consecutive matching dual-write checks, and unchanged local revision before delegating to the existing guarded server-side `promoteToNormalized`. The promotion itself checks manifest/normalized read and rolls back on failure.
- Once a server manifest is `normalized`, the existing `HerdHarborCloud.syncNow()` uses `syncNormalizedNow()` and the record CAS/outbox writer rather than legacy full-state PATCH. A temporarily stale local authority check must *not* fall through to the legacy writer.
- Normalized saves now require a non-skipped, successful drain reporting `stage: normalized`, zero failures, and no remaining record outbox. Offline or skipped work is not reported as `Saved to cloud`.
- Account-scoped hydration snapshots are fenced against local edits or changed owner/dirty state while asynchronous RPCs run. Failure to retain recovery copies now prevents destructive legacy/normalized replacement; edits during baseline writes retain their dirty marker rather than being incorrectly acknowledged.
- The PWA update guard continues to treat a legacy dirty marker as unfinished work even under normalized authority.
- The web HTML and required offline shell use new script revisions and a new S18 shell cache identity; prior shell caches are retained by the existing activation policy.

## Acceptance before any real-account switch

1. Run exact-head full CI with UTC and America/New_York suites, governance/security, release fingerprint builder, unchanged-source check, and unsigned Android review build.
2. Explicitly verify authenticated client RLS and guarded normalized authority RPC grants. Never use service-role credentials in the browser.
3. Resolve existing S17 legacy 2.0.0 PWA update-timer release blocker with a safe saved/closed-client procedure, or separately approved bridge release.
4. For **each account**: take and verify an encrypted/durable recovery backup; close or update all legacy clients and installed PWA windows; verify no dirty markers, in-memory drafts, conflicts, or pending normalized outbox; run repeated reconciliation of record counts and checksums, including deletions.
5. Test 2 users in 2 browser profiles/devices; rapid account A→B→A, simultaneous edits, airplane mode, offline outbox replay, record CAS conflicts, retries, quota denial, migrations, rabbit/dog/litter/pedigree/medical workflows, and PWA cache update.
6. Promote only a single approved account first, verify readback uses normalized records without fallback, examine logs and source checksums, and exercise a recovery rollback in staging. Remaining accounts are a separate guarded migration; merely being allowlisted is not evidence of dual-write.
7. Never delete legacy tables, existing backups, migration control, or recovery RPCs until a separate retention and rollback approval.

## Not done on this branch

- No live `herdharbor_sync_manifest` updates, no live account promotion, no schema changes, no deletion of legacy snapshots or customer data.
- No production deploy, Android publishing, merge into main, owner acceptance, real-device proof, or proof that all five accounts completed dual-write.
- The `legacy` / `dual_write` compatibility engine still exists for accounts not yet safely transitioned. It can be retired only after all remaining accounts have verified normalized authority and recovery paths are independently proven.
