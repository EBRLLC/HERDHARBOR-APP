# HerdHarbor Alpha v1.6.7 — Sign-in Deadlock Hotfix

## Symptom

A valid email/password submission can remain on the authentication screen showing **Signing in…** instead of opening the protected HerdHarbor records.

## Root cause

`herdharbor-cloud.js` registers an `onAuthStateChange` callback that immediately starts account/profile and cloud-record hydration. Those hydration paths make additional Supabase API calls. Supabase documents a `supabase-js` deadlock condition when another Supabase API call is made synchronously from an auth-state callback.

The v1.6.7 release also intentionally retains the recovered consolidated `index.html`, whose script query strings are still historical. Authentication-critical assets therefore remain network-first in the service worker so the hotfix can replace a cached release router without rewriting the large shell.

## Fix

`herdharbor-release-v1.6.1.js` loads after the vendored Supabase library and before `herdharbor-cloud.js`. It now installs a narrow `createClient` guard that wraps `auth.onAuthStateChange` callbacks and defers HerdHarbor application work to the next task. Supabase finishes its auth notification first; HerdHarbor then performs membership/profile/cloud hydration outside the auth lock.

The wrapper preserves the original Supabase client, subscription return value, event/session arguments, and synchronous callback error reporting. It changes no credentials, session storage, account data, membership policy, cloud merge semantics, or local farm records.

## Regression protection

- `tests/auth-signin-deadlock-v1.6.7.test.cjs` proves a `SIGNED_IN` callback is not executed inside the underlying Supabase auth notification and does execute immediately afterward.
- `tests/current-shell-asset-identity-v1.6.7.test.cjs` protects network-first delivery of the authentication-critical assets while `index.html` retains historical query strings.

## User recovery after deployment

Close and reopen the installed HerdHarbor app or reload the browser page once so the network-first release router is refreshed. Existing local records and the Supabase account/session data are not intentionally cleared by this hotfix.
