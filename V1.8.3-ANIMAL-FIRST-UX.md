# HerdHarbor Alpha v1.8.3 — Animal-First UX Consolidation

## Objective

Alpha v1.8.3 consolidates the existing animal-first workflow into one predictable user experience without replacing or duplicating canonical Health, Breeding, Genetics, Pedigree, Shows, Production, Sales, Tasks, or Analytics data.

The hardlocked `HH-ANIMAL-FIRST-001` contract remains authoritative.

## Why this release exists

HerdHarbor already has the correct animal-first architecture, but the UI accumulated several additive workflow layers during v1.7.1–v1.8.2. Some new-profile actions still route through the older animal-detail modal in the background before reaching the canonical form. That indirection is functional but brittle and makes the app harder to reason about.

v1.8.3 is a consolidation release, not an architecture rewrite.

## Sprint order

### 1. One animal-action router

Create one animal-aware action router for the actions launched from an animal profile.

Direct actions should no longer need to open the old animal-detail modal merely to trigger another button.

Initial direct actions:

- Add weight
- Start health episode
- Add care
- Start breeding
- Open genetics
- Add show entry

Legacy-only actions may temporarily fall through to the existing implementation until they receive a safe direct route:

- Build/import pedigree
- Print pedigree
- Edit/status
- Analytics

### 2. One profile shell

`flow-phase2` remains the authoritative animal profile shell:

- Overview
- Health
- Breeding
- Genetics
- Pedigree
- Shows
- Production
- History

The older modal profile hub remains compatibility-only and must not become a second normal animal-profile experience.

### 3. Predictable return behavior

When a user launches a domain form from an animal profile, completing or closing the form should return them to the same animal and tab whenever practical.

### 4. Contextual Quick Add consolidation

Quick Add should use the same animal-action routing rules rather than maintaining separate animal-specific launch behavior.

### 5. Mobile profile polish

- Keep primary animal identity visible without excessive scrolling.
- Make profile tabs usable on narrow screens.
- Keep the highest-frequency actions reachable without opening multiple menus.
- Avoid duplicate action rows.

### 6. Remove compatibility indirection

Once direct routes are proven, remove background modal-bridge behavior for those actions.

Do not remove the stable canonical domain forms or engines.

### 7. Regression gate

v1.8.3 must preserve:

- cloud-sync/state-integrity behavior from v1.8.2;
- animal lifecycle write semantics;
- current-farm species context;
- quarantine breeding safeguards;
- canonical pedigree links;
- sales/transfer state;
- paper-pedigree import;
- Android/PWA packaging.

## Explicitly outside v1.8.3

These remain later roadmap releases:

- expanded Today/reminders/farm operations (1.9.0);
- full document management (1.9.5);
- voice/photo general record entry (2.1);
- new breeding intelligence architecture (2.2);
- CRM/business tooling (2.5);
- multi-farm Business platform (3.0).

The paper-pedigree scanner was delivered early during v1.8.2 stabilization and does not change this release order.
